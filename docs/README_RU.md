## Зачем

Когда пропадает интернет, обычные утилиты отвечают на один вопрос: жив ли какой-то адрес. TashevNet отвечает на те вопросы, которые на самом деле возникают:

- **Что сломалось?** Wi-Fi и роутер, провайдер, DNS, сами сайты или VPN?
- **Когда и надолго ли?** Каждый сбой записывается с началом и длительностью.
- **Упал ли VPN, не утекает ли трафик мимо него?** Программа следит за интерфейсом VPN и, если попросить, за вашим внешним IP.
- **Помогло ли восстановление?** Она может сама выполнить вашу команду переподключения VPN и сообщить результат.

Всё работает на вашем компьютере, история лежит в локальном файле SQLite, учётная запись не нужна.

## Где оборвалось

Каждая проверка (по умолчанию раз в 5 секунд) проходит все звенья цепочки и называет первое, которое не отвечает.

| Звено | Как проверяется | Что значит сбой |
|---|---|---|
| Роутер | ping физического шлюза; он находится даже за VPN, который забирает весь трафик | проблема Wi-Fi или локальной сети. Учитывается, только если интернет тоже недоступен: многие роутеры просто не отвечают на ping |
| VPN | интерфейс, через который реально идёт трафик в интернет (по таблице маршрутов), и по желанию ожидаемый внешний IP | VPN отключился или трафик идёт мимо туннеля |
| Интернет | ping 1.1.1.1 и 8.8.8.8; если ping закрыт или подделан, HTTPS-запрос, на который может ответить только настоящий сервер | авария у провайдера или дальше |
| DNS | разрешение нескольких известных имён | имена перестали разрешаться, хотя сам интернет работает |
| Сайты | обычный HTTPS-запрос страницы | веб-запросы не проходят, хотя DNS работает |
| Качество линии | медиана задержки за последние пять проверок | линия медленная, выше вашего порога (по умолчанию 250 мс) |

## Честно даже за прокси-VPN

Многие VPN-приложения в режиме TUN (sing-box, Clash, Xray и клиенты на них) сами принимают любое TCP-соединение прямо на вашем компьютере, а некоторые ещё и отвечают на ping за любой адрес. Монитор, который верит таким ответам, показывает зелёный свет, когда туннель давно мёртв.

TashevNet сначала стучится на `203.0.113.1` — документационный адрес, на который в интернете не отвечает никто. Если этот стук «прошёл», значит отвечает ваш же компьютер. Тогда такие ответы игнорируются, и учитываются только настоящие HTTPS-ответы с другой стороны. Панель прямо пишет об этом.

## Уведомления, которые хочется читать

- Один потерянный пакет — не авария: проблема становится инцидентом, когда видна в 2 из 3 последних проверок.
- Мигающая линия даёт один инцидент, а не сообщение каждые 5 секунд: для восстановления нужны 3 чистые проверки подряд.
- Каждое восстановление сообщает, сколько длился сбой: `🟢 back to UP after 4 min 12 s`.
- Уведомления, которые не удалось отправить без интернета, ждут в очереди и приходят по порядку, как только связь вернётся.

## Быстрый старт

```bash
git clone https://github.com/tashev11/tashevnet.git
cd tashevnet
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
cp config.example.yaml config.yaml
tashevnet doctor
tashevnet run
```

Откройте **http://127.0.0.1:8765**. Windows, Docker и автозапуск описаны в [INSTALL.md](../INSTALL.md).

| Команда | Что делает |
|---|---|
| `tashevnet run` | мониторинг, панель и Telegram-бот |
| `tashevnet once` | одна проверка в виде JSON; код выхода 2, если связи нет; ничего не записывает |
| `tashevnet doctor` | проверяет файл настроек, папку базы, настройки Telegram и нужные утилиты |
| `tashevnet telegram-id` | показывает чаты, которые недавно писали вашему боту |

### Telegram за минуту

1. Создайте бота через **@BotFather** и напишите ему любое сообщение.
2. Узнайте ID своего чата:
   ```bash
   export TASHEVNET_TELEGRAM_BOT_TOKEN="123456789:AA..."
   tashevnet telegram-id
   export TASHEVNET_TELEGRAM_CHAT_ID="123456789"
   ```
3. Поставьте `telegram.enabled: true` в `config.yaml` и перезапустите `tashevnet run`.

Бот отвечает на `/status`, `/vpn`, `/events` и `/ping` и только в вашем чате. Подробнее: [TELEGRAM.md](TELEGRAM.md).

## Настройки

Любую настройку можно не указывать, полный список — в [config.example.yaml](../config.example.yaml). Опечатка в названии настройки считается ошибкой, а несуществующий путь в `--config` останавливает запуск, вместо того чтобы молча взять настройки по умолчанию.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `monitor.interval_seconds` | `5` | пауза между проверками |
| `monitor.alert_after_checks` | `2` | сколько плохих проверок из последних трёх делают инцидент |
| `monitor.recover_after_checks` | `3` | сколько чистых проверок подряд его завершают |
| `monitor.degraded_latency_ms` | `250` | задержка линии, которая считается ухудшением |
| `monitor.vpn_required` | `false` | считать отсутствие VPN аварией |
| `monitor.vpn_expected_ip` | пусто | внешний адрес вашего VPN; любой другой IP — утечка |
| `monitor.self_heal_vpn_command` | пусто | команда переподключения VPN; её останавливают через `self_heal_timeout_seconds` |
| `monitor.retention_days` | `30` | сколько хранить историю; чистка раз в час |
| `speed.enabled` | `true` | небольшой замер скачивания и отдачи раз в час |
| `telegram.enabled` | `false` | уведомления и команды бота |

Переменные окружения важнее файла: `TASHEVNET_CONFIG`, `TASHEVNET_TELEGRAM_BOT_TOKEN`, `TASHEVNET_TELEGRAM_CHAT_ID`, `TASHEVNET_HOST`, `TASHEVNET_PORT`, `TASHEVNET_DB_PATH`.

## API

| Адрес | |
|---|---|
| `GET /api/status` | подтверждённое состояние, последняя проверка и влияющие на неё настройки |
| `GET /api/events?limit=25` | последние смены состояния, новые сверху, с длительностью сбоев |
| `POST /api/check` | проверить сейчас; нужен заголовок `X-TashevNet: check` |
| `GET /healthz` | `200`, пока проверки идут, и `503`, если они остановились |
| `GET /api/docs` | интерактивный справочник OpenAPI |

## Что и куда отправляется

- Ping на `1.1.1.1` и `8.8.8.8`, несколько DNS-запросов и один небольшой HTTPS-запрос к Cloudflare за проверку, по уже открытому соединению.
- Внешний IP с `api.ipify.org` раз в 30 секунд и при каждой смене состояния VPN.
- Замер скорости раз в час передаёт около 2,5 МБ, примерно 60 МБ в сутки. На лимитном интернете его стоит выключить.
- API Telegram — только если вы включили бота. Никакой телеметрии, учётных записей и облака.

## Состояние и ограничения

Проект молодой. Версию 0.1.1 проверяли на macOS с Python 3.12 и 3.14, в том числе вживую за прокси-VPN; автоматических тестов 84.

- Юнит для systemd и образ Docker в комплекте, но на настоящем сервере в этом выпуске не запускались. Поддержка Windows написана, но не проверена.
- VPN определяется по именам интерфейсов и маршрутам; VPN с раздельным туннелем считается подключённым.
- Компьютер без интернета не может сам отправить уведомление. TashevNet доставит его после восстановления, а мгновенные уведомления о пропаже связи требуют внешнего наблюдателя, он в [планах](../ROADMAP.md).
- У панели нет входа по паролю. Держите её на `127.0.0.1`.
